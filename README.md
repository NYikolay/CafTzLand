# Реализация тестового задания

**Основной стек:** Next.js (frontend), FastAPI (backend), Postgres, Nginx (прокси)  
**ИИ агент:** OpenCode  
**Модель:** DeepSeek V4.1 Flash

## Реализованы следующие фичи:
1. Landing PAGE согласно ТЗ
2. REST API с Admin панелью. Поставил кэширование на стороне сервера, поэтому обновления контента из админки через час инвалидируются у клиента - можно и убрать:)
3. Пересылка оформленного заказа в Telegram чат с ботом
4. Проект задеплоен на личный VPS сервер, получен SSL сертификат

**Выбор стека** (в частности backend на FastAPI) обоснован желанием показать навык. Само собой текущая реализация такой простой задачи является оверхедом и всё можно сделать проще, но упор был на другое.  
Самым идеальным вариантом реализации этой задачи (если она реальна) является дефолтный MPA (Django, PHP, в целом и Next.js подойдёт) - для лендинга этого достаточно

## Работа с агентом:

Логи сессий можно найти в директории `opencode_session`

Весь принцип работы построен на подходе Subagent-Driven Development и использовании навыка superpowers. В первую очередь пишется спецификация и план, далее идёт реализация с использованием субагентов  
Работа не ведётся в одной сессии, каждая новая фича - отдельная сессия. При небольшом контекстном окне после написании спеки и плана делается compact контекста и выполняется реализация в этой же сессии.  
Разбивка на сессии обоснована уменьшением интеллекта агента (в частности LLM модели) по меры роста контекстного окна.

## Процесс создания проекта:
1. Дизайн был сформирован в бесплатном агенте Figma согласно тз. Пару мелких правок было сделано руками (где-то текст изменил, где-то цвет).
2. Для работы с фигмой был использован локальный MCP. Через Desktop приложение
3. Далее реализация скелета бэка и фронта. Тут уже делал всё агент. 
4. Разбил проект на более-менее мелкие задачи (в логах сессий можно увидеть).
5. Деплой на VPS, получение сертификата (руками делал)

Ошибок как таковых агент не допускал. Благодаря SDD и TDD агент чётко понимает что ему делать, сам себя ревьюит и задаёт вопросы когда чего-то не понимает. Количество ошибок минимально, главное чётко описать задачу.

## Из проблем:
1. Пару багов в вёрстке, незначительных. Что-то поправил руками, что-то между задачами
2. Показатель производительности на мобилка по Lighthouse изначально был 88. Из-за шрифтов, слишком много файлов подгружало - часть убрал. В тоге показатель 92, можно больше если оставить 1 разновидность шрифтов и поиграться с картинками - но в целом и так результат хороший.


Не знаю, оцениваете ли вы скорость реализации. В целом всё можно было бы сделать быстрее: низкий TPS на провайдере модельки у подписки агента :(, ну и выбор технологий. На джанге это бы всё сделалось за пару промптов. Плюс на задаче был сосредоточен не full time - но старался сделать побыстрее
